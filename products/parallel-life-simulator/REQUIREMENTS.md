# 岔路人生：内容吸引力需求

更新时间：2026-08-18

本文件把 `RESEARCH.md` 中的研究建议转成产品需求。以下内容作为后续原型和实现的需求基线。

## 本轮目标

提升“节点改写后继续看下一年”的吸引力。

成功不是让页面更多，而是让用户在一次改写后自然产生四个行为：

- 愿意在三个选项里做选择。
- 能说出为什么这个选择难。
- 选择后愿意连续查看接下来三年。
- 看完三年后愿意保存版本，或回头尝试另一条路。

## 核心需求

### R1：改写后必须逐年揭晓三年余波

每次节点改写后，当前年及后续节点仍保持在同一条时间轴上，但改写起点后的前三年必须被当作一个连续叙事单元设计。

结构要求：

- 第 1 年：行动发生。用户能看懂人物具体做了什么。
- 第 2 年：代价显形。眼前收益之外的现实压力必须变具体。
- 第 3 年：验证、反噬或再协商。选择必须改变人物的关系、资源、自我判断或行动意愿。

验收标准：

- 用户确认改写后，不应一次性把前三年全部摊开；应通过逐年揭晓让用户主动查看下一年。
- 三年标题不能只是同义替换。
- 三年详情必须能连成因果链。
- 第 2 年至少出现一个具体代价，而不是笼统“压力变大”。
- 第 3 年必须让用户理解这条路不是单纯变好或变坏。

### R2：每个选项必须包含可见代价和隐藏代价

选择前展示：

- 眼前得到：这个选择马上帮人物获得什么。
- 现实代价：用户在选择前能预见的成本。

选择后揭示：

- 隐藏代价：人物当时没有完全预见，但现实中合理会发生的复杂后果。

隐藏代价的规则：

- 隐藏代价不需要在 UI 上标注“当时没想到”，应通过节点事件和叙事自然体现。
- 不能像惩罚用户。
- 不能用系统口吻教育用户。
- 必须来自人物上下文，比如钱、父母、伴侣、职业身份、身体或朋友关系。
- 必须在后续节点里自然显影，而不是弹出分析报告。

验收标准：

- 用户选择前能感到取舍，而不是三条路都像正确答案。
- 用户选择后第二年能看到“原来还有这一层”的现实复杂性。
- 隐藏代价不得否定用户的选择，只能增加真实感。

### R3：年度节点必须有克制钩子

年度标题和摘要要从“状态报告”改成“生活钩子”。

写法要求：

- 标题优先呈现具体变化，而不是抽象状态。
- 钩子必须克制可信，不使用狗血、夸张、命运式表达。
- 事实、关系、心理、资源变化要交替出现，避免全是情绪句。

示例标准：

- 弱：“生活逐渐稳定。”
- 强：“她开始熟练地结束父母的话题。”
- 弱：“职业能力提升。”
- 强：“一个小项目第一次让她不只是执行者。”

验收标准：

- 用户只看五年窗口标题，也能感到每一年有不同问题。
- 标题不依赖省略号，不截断关键含义。
- 每个标题都能在节点详情中找到具体事件支撑。

### R4：高强度事件必须进入路径记忆

已经发生过的高强度事件，后续不能当作第一次重复发生。

需要进入路径记忆的事件类型：

- 婚育边界表达。
- 辞职、转岗、裸辞。
- 搬家、迁移、回老家。
- 分手、复合、进入共同生活。
- 重大健康警讯。
- 买房、负债、收入结构明显改变。

后续可写：

- 余波。
- 反复。
- 关系冷却或修复。
- 压力换形态。
- 边界维护。
- 新阶段的再协商。

后续不可写：

- 把同一件事重新写成第一次摊牌、第一次辞职、第一次离开。
- 忘记已发生的资源、关系或身份变化。

验收标准：

- 用户保存版本后继续改写后续节点，系统仍记得前面的高强度事件。
- 后续选项会根据路径记忆替换掉不合时宜的第一次行动。

### R5：现实困局必须前置到创建人物流程

创建人物时必须收集现实困局，而不是只依赖姓名、年龄、城市和职业。现实困局主要由用户输入，AI 只能负责整理、追问和结构化，不应凭空替用户编造人生困局。

优先收集的信息：

- 最近最烦的一件事。
- 最想保住的东西。
- 最不想承认的担心。
- 正在施压的关系。
- 当前最怕付出的代价。

实现约束：

- 不应一次性把创建流程变成长问卷，但创建入口必须至少有一个现实困局输入。
- 用户输入可以很短、很乱，产品负责整理成可推演字段。
- AI 可以提供默认样例或改写建议，但真实个性化必须来自用户输入。
- 输入应转化为事件、选择和后果，而不是分析报告。
- 首次输入后采用自适应 1 至 3 问：只补充会实质改变路径或后果的信息，已经明确的内容不得重复询问。
- 追问一次只显示一题，并显示当前进度；回答以语境化选项为主，必须允许“暂时说不清”和自由补充。
- 追问结束后，系统先用第三人称复述对困局的理解；用户确认或修正后才生成三条路径。

验收标准：

- 创建人物后，人物档案或首个推演版本能体现用户输入的现实困局。
- 用户能在生成路径里看到自己输入的困局被具体使用。
- 三条路径不是职业模板，而是围绕困局展开。
- 信息完整的输入可以只追问一题，信息不足时最多追问三题，不得为了固定流程凑数。
- 每个追问都必须能对应到至少一个路径差异或后果差异。
- 用户可以否定全部系统路径并输入自己的行动。

### R6：AI 只能服务结构化推演

AI 可以用于增强内容，但不能成为主体验。

允许用途：

- 把人物输入归纳为现实困局。
- 生成三年余波的候选事件，并交给产品结构校验、兜底和保存。
- 生成符合人物上下文的隐藏代价。
- 为节点补充冷静可信的第三人称旁白。
- 给出后果依据或假设标签。

禁止用途：

- 直接给用户人生建议。
- 输出长篇分析报告作为主结果。
- 生成不可复现、不可比较的随机版本。
- 用漂亮文案掩盖选择设计薄弱。
- 把产品变成开放式陪聊。

验收标准：

- AI 生成结果必须落入节点、选项、代价或依据等结构化字段。
- AI 不通、超时或生成内容不合格时，必须回退到本地规则，不阻断改写流程。
- 保存后的版本必须可回看、可比较。
- 没有 AI 或 API 不通时，产品仍能完成基础推演。

### R7：推演必须形成可追溯的因果链

推演不是把用户资料换进通用故事。事实、假设、行动机制和结果必须能被分别识别，条件改变后候选路径和年度后果也应随之改变。

路径选择前必须包含：

- 具体行动，而不是抽象态度。
- 行动通过什么机制改变局面。
- 这条路成立所依赖的条件。
- 到什么时间观察什么信号。
- 最可能从哪个维度出现代价转移。

年度节点必须包含：

- 直接来自用户输入、追问回答或前一年结果的原因。
- 可以观察的生活变化，而不只是情绪评价。
- 至少一个仍不能确定的外部条件。
- 有上下文依据的状态相对变化；绝对分数不能被当作预测证据。

验收标准：

- “职业承诺未兑现 + 收入底线 + 伴侣共同财务计划”应生成验证内部承诺、在职验证外部机会、重排共同计划三种不同机制，而不是三条通用建议。
- 改变现金缓冲、伴侣态度或等待期限后，路径条件、复盘点或年度代价至少有一项发生变化。
- 第二年的原因必须能够回溯到第一年行动，第三年必须抵达选择前展示的复盘信号。
- 首次三年没有揭晓完成前，不得提前展示更远年份，也不得通过二次改写、设置或延伸绕过流程。
- 首次保存只包含三年可解释节点，未经用户选择的自动基线不进入版本列表。

## 首个验证原型

“R1 逐年揭晓三年余波 + R2 隐藏代价自然体现 + R3 年度钩子”的窄范围原型已经实现；2026-08-18 接通了 R5 自适应追问和 R6 结构化 AI 候选链路，2026-08-24 接通了 R7 结构化因果链。下一步是目标用户验证，不再继续用增加页面代替验证。

当前实现范围：

- 新建人物先走轻量现实困局流程，完整七维画像移到之后编辑。
- 根据输入缺口自适应追问 1 至 3 题，确认困局后再展示三条路径。
- 支持“这都不是她/他/TA会做的”自定义行动。
- 外部模型可生成结构化候选，未配置、超时或校验失败时使用本地婚育、健康、城市和通用困局内容。
- 三年看完后提供保存、换路和修改条件。

推荐交互：

1. 用户选择一个节点改写。
2. 弹窗展示三项行动、眼前得到、现实代价。
3. 确认后先只生成当前可解释的三年范围。
4. 改写起点后的第 1 年先被揭晓。
5. 用户继续查看第 2 年，看到代价自然显形。
6. 用户继续查看第 3 年，看到验证、反噬或再协商。
7. 三年完成后，用户可保存版本、换路或修改条件；更远未来之后再明确延伸。

验证问题：

- 用户最想选哪条路？
- 哪个代价让选择变难？
- 第 2 年是否让用户想看第 3 年？
- 第 3 年是否让用户想保存版本？
- 用户是否觉得系统记得前面发生过什么？

## 内容优先级

第一批优先做交叉困局，不做单一题材模板。

优先组合：

- 职业停滞 + 父母压力 + 钱。
- 职业转向 + 收入下降 + 亲密关系。
- 城市去留 + 家庭期待 + 安全感。
- 身体报警 + 工作节奏 + 自我价值。

暂缓组合：

- 纯恋爱爽文。
- 纯职场升级。
- 纯财富逆袭。
- 纯心理疗愈。
