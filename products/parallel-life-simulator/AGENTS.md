# 岔路人生协作规则

本文件适用于 `products/parallel-life-simulator/` 及其所有子目录。

## 接手顺序

开始修改前，必须按顺序阅读：

1. `PRODUCT.md`：理解产品定位、用户与体验原则。
2. `DECISIONS.md`：确认已定规则、已否决方案和仍待决定的问题。
3. `RESEARCH.md`：了解内容吸引力研究、外部信号和可借鉴原型。
4. `REQUIREMENTS.md`：确认已转成需求的内容增强方向和验收标准。
5. `CONTENT_PROTOTYPES.md`：查看首次推演的三组校准样例和内容质量基线。
6. `STATE.md`：了解当前实现、已知限制和最近验证结果。
7. 最近与本产品有关的 Git 提交。

用户最新的明确指令始终拥有最高优先级。如果新指令改变既有决定，应执行新指令，并同步更新文档，不能让代码和产品记忆互相矛盾。

## 修改纪律

- 不得重新引入 `DECISIONS.md` 中已否决的交互，除非用户明确推翻原决定。
- 建议、猜测和已确认需求必须分开记录，不能把讨论中的设想直接写成既定需求。
- 保持第三人称、冷静可信和沉浸感，不把推演描述成命运预测。
- 优先保护人物、版本、草稿和时间轴的既有数据语义。
- 继续使用本地依赖，不添加外部 CDN。密钥、Token 和密码不得进入仓库。
- 产品必须继续由 `app.toml` 托管，启动命令读取 `$PORT` 并绑定 `0.0.0.0`。
- 工作区可能包含其他产品的未提交修改，只提交本目录中与任务有关的文件。

## 完成标准

每次产品行为发生变化后：

1. 运行 `node --check app.js` 和 `git diff --check`。
2. 用浏览器验证受影响的完整流程，而不只检查单个按钮。
3. 至少检查 1366x768 桌面和 390x844 手机视口的溢出与遮挡。
4. 新的产品决定写入 `DECISIONS.md`。
5. 当前能力、限制或下一步发生变化时更新 `STATE.md`。

`STATE.md` 是可更新的当前快照；`DECISIONS.md` 是决定历史，不应为了让文档简洁而删除仍有约束力的旧决定。
