# 岔路人生：当前状态

更新时间：2026-08-18

## 当前实现

产品位于 `products/parallel-life-simulator/`，是一个由平台托管的零前端依赖 Web 应用，包含本地 Python 同源代理。

- `index.html`：应用外壳、导航、弹窗和安全策略。
- `styles.css`：桌面、矮屏桌面和手机响应式布局。
- `app.js`：人物、现实困局、版本、草稿、时间轴、规则推演、本地存储和导入导出。
- `app.toml`：平台托管配置，使用 `$PORT` 并绑定 `0.0.0.0`。
- `server.py`：静态文件服务和 OpenAI 兼容 `/api/llm/chat` 代理。
- `RESEARCH.md`：内容吸引力研究，整理外部数据、竞品机制和待验证原型。
- `REQUIREMENTS.md`：内容吸引力需求，把三年余波、隐藏代价、年度钩子、路径记忆和 AI 边界转成需求与验收标准。
- `CONTENT_PROTOTYPES.md`：三组首次推演内容原型，分别校准自适应 3、2、1 问和三年余波质量。

已实现：

- 人物空间和多人物管理。
- 自我探索与观察人物两种人物类型。
- 新建人物使用轻量现实困局流程，不先要求调整七维画像；输入人物基本上下文和困局后，按信息缺口自适应追问 1 至 3 题。
- 追问一次一题，支持语境化选项、“暂时说不清”和自由补充；回答会被整理成困局摘要、人物边界、约束与假设，用户确认后才进入路径选择。
- 困局确认后展示三项具体行动，并提供“这都不是她/他/TA会做的”自定义行动入口。
- 七维人物画像及按身份估计。
- 人物档案、五年时间窗口和完整轨迹总览。
- 节点选择、同轴改写、放弃草稿和保存新版本。
- 节点改写中的三项行动选择：选择前展示眼前收益与现实代价，选择后生成至少三年的连续因果节点。
- 节点改写后前三年余波按年揭晓：先显示行动发生年，后两年以“尚未揭晓”遮住；用户逐年查看后，保存新版本才放行。
- 首次三年余波看完后，可直接保存这条路、回到三条路径尝试另一条，或返回修改追问条件；换路不会重复创建人物。
- 对包含催婚或婚育压力的人物，路径允许不婚、晚婚、丁克、暂不决定或改变想法，并将父母意见作为外部压力而非人生目标。
- 压力通过适应、代价转移和事件再触发进入叙事，不显示为持续累加的用户数值。
- 同一路径已说清婚育边界后，再次改写不会重复提供“第一次摊牌”，而是改为维护既有边界；后续节点也只呈现边界被测试或压力换形态。
- 节点和版本增加显式路径记忆，覆盖婚育边界、辞职、转岗、迁移、分手、共同生活、健康警讯、买房、负债、收入变化和自由职业；后续候选会过滤已经发生过的第一次行动。
- 继续五年、10/15/20 年观察跨度和现实强度设置。
- 已保存版本切换和逐年版本对照。
- 本地历史记录、旧数据迁移、JSON 导入和导出。
- 时间推演返回人物档案、人物档案返回人物空间的连续导航。
- 可选的本地 AI 连接器：在浏览器内保存 OpenAI 兼容的 base URL、模型名和密钥，通过本地代理 `/api/llm/chat` 请求模型，默认模型为 `gpt-luna`。配置后可生成结构化追问、困局摘要、三项行动和三年余波；结构不合格、超时或请求失败时自动回退到本地婚育、健康、城市和通用内容。
- AI 设置明确提示哪些人物内容会发送到外部上游，并支持单独清空配置与密钥。
- 人物及其全部版本可以删除；导出的工作区备份不包含单独保存在另一个 localStorage 主键下的 API Key。

## 数据语义

- localStorage 主键：`forked-life-workspace-v2`。
- 旧数据主键：`future-life-state`，加载时自动迁移。
- 未保存草稿只存在于当前页面内存，不进入 localStorage，也不增加版本数量。
- 保存草稿后创建新版本并切换为活动版本。
- 修改人物画像不会修改版本节点中已经保存的状态。
- 新建流程的追问、回答、困局摘要和候选路径保存在 `person.intake`；保存版本时会冻结 `choiceMeta`、`assumptions` 和 `pathMemory`。

## 已知限制

- 当前推演规则仍以预设事件、场景模板和数值传播为主，人物之间的长期内容可能趋同。
- 路径记忆已经结构化扩展到多类高强度事件，但后续本地选项库仍主要覆盖婚育、健康、城市和通用策略，尚未为分手、买房、负债等每类事件写完整的余波库。
- 首次困局确认和未保存草稿会展示假设，已保存版本对照页尚未专门解释因果依据；产品仍不展示缺少证据基础的概率数字。
- 场景视觉由本地 CSS 生成，尚无真实 CG 素材。
- 数据只保存在当前浏览器，没有账户、云同步和跨设备恢复。
- 当前工作区无法连通用户提供的 `ai-newapi.cloudglab.cn`，`curl` 请求在本环境里超时；AI 连接器代码已接入，但该外部接口尚未在此环境中实测成功。
- 尚未进行目标用户测试，当前判断主要来自产品创建者的连续体验反馈。
- 版本目前不能重命名或删除；人物已经可以删除。
- 结构化 AI 生成目前只接入新建人物的首次困局流程，已有版本的普通节点改写仍使用本地选择与余波。
- 完整增强循环已经实现为可体验原型，但尚未进行目标用户验证，不能据此判断它已经形成长期留存。

## 最近反馈

用户认为产品已经比早期原型更像完整产品，但仍不能充分吸引用户兴趣。当前判断是：界面和管理能力已经超过推演内容本身，下一步不应只继续增加页面，而应验证个性化事件、选择张力、现实代价和逐步揭晓是否能形成留存。

当前已经确认把内容吸引力研究转成需求。本轮在原有窄范围原型上接通了首次困局完整闭环，但仍把它视为待用户验证的产品假设。

2026-08-17 新增内容研究并转成需求：外部数据和竞品机制都指向“短钩子、连续后果、个人相关性、选择代价”。用户已确认三年余波要逐年揭晓，隐藏代价通过剧情自然体现，AI 可以参与生成候选三年余波但必须有本地规则兜底；现实困局要前置到创建人物流程，由用户输入，AI 只负责整理、追问和结构化。

2026-08-18 用户确认首次输入后需要追问、需要“这都不是她/他/TA会做的”自定义行动入口，并接受第一阶段三年后先保存、换路或修改条件。首次追问确定为自适应 1 至 3 问：一次一题，选项加自由补充，已经明确的信息不重复询问。页面交互、结构化 AI 候选、本地回退、路径记忆和隐私删除入口均已实现。

## 验证基线

最近一次完整验证结果：

- `node --check app.js` 通过。
- `python3 -m py_compile server.py` 通过。
- `git diff --check` 通过。
- 使用全局 Playwright 直接加载本地产品文件完成桌面和手机浏览器验证；没有启动临时产品服务，平台托管配置保持不变。
- 新建“许然”并输入职业停滞、换工作和父母催婚的交叉困局后，系统按缺口追问 3 题；回答返回上一步仍保留，摘要确认后出现三条婚育与职业路径和自定义行动。
- 新建输入充分的健康困局只追问 1 题；本地回退正确提供降载、内部转岗和三个月边界试验，不会因为出现“父母”二字错误进入催婚路径。
- 选择路径后只立即展示第一年，后两年保持隐藏；看完第三年出现“保存这条路 / 尝试另一条 / 修改条件”。换路后人物总数不增加。
- 自定义行动可以生成本地三年余波；保存版本后，追问、假设和 `job_change`、`income_change` 等路径记忆进入持久数据。
- 结构化 AI 分支通过浏览器 mock 验证：模型生成的追问、困局摘要、三项行动和三年余波能通过校验进入同一条时间轴。真实 `gpt-luna` 外部接口仍因当前环境连接超时而未验证。
- 删除人物会同时删除其版本；AI 配置与密钥可以清空；备份仍不包含密钥。
- 节点改写弹窗展示三项具体行动、眼前收益和现实代价；未选择时不能确认，页面不再出现“变化幅度”控制。
- 选择“接受降薪，转去更小的业务团队”后，先显示 2026 年行动发生，2027 和 2028 年显示为“尚未揭晓”；点击“查看下一年”后依次打开“安全垫开始变薄”和“能力被结果验证”。
- 三年余波未看完前，“保存新版本”禁用；看完前三年后保存成功，版本名正确进入版本列表。
- 新建人物未填写现实困局时不能创建；填写“不想结婚、可能丁克、父母催婚”后，人物档案和首个推演节点都展示该困局。
- 新建人物的现实困局会参与改写选项判断：包含父母催婚或婚育压力时，改写弹窗提供“先把婚育边界和父母说清楚”。
- 选择“先把婚育边界和父母说清楚”后，2029 只呈现旧边界被婚礼场合测试；保存后在 2029 再次改写，弹窗提供“维持已经说过的婚育边界”，不再重复第一次摊牌。
- AI 连接器已接入并能通过 `/api/llm/chat` 命中一个 OpenAI 兼容的本地 mock；代理会拒绝非本机 HTTP 上游，避免成为任意开放转发器。用户给出的 `ai-newapi.cloudglab.cn` 在本工作区内仍然超时，真实外部接口尚未连通成功。
- 旧的未编辑内置样例可迁移到 32 岁运营人物并补齐现实困局；其他人物使用通用改写选择，不会被强行加入婚育困局。
- 创建人物、编辑画像、按身份估计、五年延伸、节点改写、草稿保存、版本对照、导入和导出均通过浏览器测试。
- 1366x768 桌面视口无页面级横向溢出；核心推演在常见桌面视口内可完成操作。
- 390x844 手机视口无页面级横向溢出；三选一弹窗、逐年揭晓按钮和保存按钮在移动端可达。
- 390x844 手机视口的新建、单题追问和四项路径弹窗均在视口内可操作；首次弹窗不再因自动聚焦而裁掉顶部标题。
