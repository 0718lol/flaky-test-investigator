# 岔路人生：当前状态

更新时间：2026-08-27

## 当前实现

产品位于 `products/parallel-life-simulator/`，是一个由平台托管的零前端依赖 Web 应用，包含本地 Python 同源代理。

- `index.html`：应用外壳、导航、弹窗和安全策略。
- `styles.css`：桌面、矮屏桌面和手机响应式布局。
- `app.js`：人物、现实困局、版本、草稿、时间轴、规则推演、本地存储和导入导出。
- `app.toml`：平台托管配置，使用 `$PORT` 并绑定 `0.0.0.0`。
- `server.py`：静态文件服务和 OpenAI 兼容 `/api/llm/chat` 代理。
- `RESEARCH.md`：内容吸引力研究，整理外部数据、竞品机制和待验证原型。
- `REQUIREMENTS.md`：内容吸引力需求，把三年余波、隐藏代价、年度钩子、路径记忆和 AI 边界转成需求与验收标准。
- `CONTENT_PROTOTYPES.md`：三组首次推演内容原型，分别校准自适应 3、2、1 问和三年余波质量。

已实现：

- 人物空间和多人物管理。
- 人物空间在已有角色和空状态下都只显示一个创建人物入口，避免页头按钮与人物网格新增卡片重复。
- 创建人物后的背景补充入口已明确为“编辑人物背景”；人物档案页头和时间推演侧栏均可直接打开同一编辑弹窗。
- 背景修改现在记录 `backgroundRevision`，人物档案会显示“重新生成推演”入口；旧版本保持不变，新推演沿用人物进入追问流程。三节点版本的时间轴标题统一显示“三年因果窗口”，不再误称“五年窗口”。
- 背景更新后人物档案主按钮会切换为“按新背景重新推演”，不再默认打开旧轨迹。
- 版本列表现在支持删除旧版本；至少保留一个版本，删除当前版本会自动切换。首次三年窗口改为六个半年节点，最后一个节点才是三年检查点。
- 半年节点生成已改为预测反馈而非复制输入：拆分节点不再复用原始 detail，过长背景型自定义行动会被收敛，机械复述和“开始执行+原文”会被校验拒绝并回退本地预测。
- 半年节点正文已移除“不能证明这条路会怎样”等重复免责声明；模型生成再次出现这类方法性旁白会被内容校验拒绝。
- DeepSeek 余波协议已从三个年度段落改为六个独立半年节点；每个 detail 要求 3 至 5 句且不少于 80 字，过短内容会整组回退到本地六节点叙事。
- 节点详情新增“补充人物反应”。用户输入的反应保存在当前节点，前面节点不变，后续半年节点通过 DeepSeek 或本地因果延伸重算，查看完成后再保存为新版本。
- 旧三节点版本会显示升级提示，可生成六个半年节点的未保存草稿；原三节点版本仍保留，避免静默改写历史。
- 在读阶段增加硬约束：定向培养只描述毕业去向，未明确实习、规培、兼职或入职时，AI 节点中的正式就业和工资情节会被判为不合格并回退。
- 自我探索与观察人物两种人物类型。
- 新建人物使用轻量现实困局流程，不先要求调整七维画像；输入人物基本上下文和困局后，按信息缺口自适应追问 1 至 3 题。
- 追问一次一题，支持语境化选项、“暂时说不清”和自由补充；回答会被整理成困局摘要、人物边界、约束与假设，用户确认后才进入路径选择。
- 困局摘要同时建立结构化因果上下文，区分题材、已知事实、关键变量、现实约束、待确认假设和仍不确定项。
- 困局确认后展示三项具体行动，并提供“这都不是她/他/TA会做的”自定义行动入口。
- 每条候选路径包含行动机制、成立条件、检查点、主要风险和直接因果因素；本地职业模型已覆盖“工作承诺 + 收入安全 + 伴侣共同财务计划”的交叉困局。
- 七维人物画像及按身份估计。
- 人物档案、五年时间窗口和完整轨迹总览。
- 节点选择、同轴改写、放弃草稿和保存新版本。
- 节点改写中的三项行动选择：选择前展示眼前收益与现实代价，选择后生成至少三年的连续因果节点。
- “小实验”选项已按困局具体化：职业为三个月目标方向小项目，健康为三个月降载与复查，迁移为一个月试住，关系为三个月固定见面与沟通；每项都带有动作、周期和复盘标准。
- 节点改写后前三年余波按年揭晓：先显示行动发生年，后两年以“尚未揭晓”遮住；用户逐年查看后，保存新版本才放行。
- 年度节点显示“因为 -> 所以 -> 仍需观察”，保存直接原因、可观察变化和不确定项；七维状态在年度页优先显示相对变化和当前值。
- AI 余波会拒绝内部模板泄漏、空泛代价和原因/结果/不确定项互相重复；关系中的主动投入会与当年关系数值保持一致，除非正文同时存在明确的反向事件。
- 首次三年未完成前，所有更远年份保持隐藏，二次改写、推演设置和继续五年均不可进入。
- 首次推演只生成并保存三个可解释节点，自动初始基线在首次保存时被替换，不再作为用户版本保留。
- 首次三年余波看完后，可直接保存这条路、回到三条路径尝试另一条，或返回修改追问条件；换路不会重复创建人物。
- 对包含催婚或婚育压力的人物，路径允许不婚、晚婚、丁克、暂不决定或改变想法，并将父母意见作为外部压力而非人生目标。
- 压力通过适应、代价转移和事件再触发进入叙事，不显示为持续累加的用户数值。
- 同一路径已说清婚育边界后，再次改写不会重复提供“第一次摊牌”，而是改为维护既有边界；后续节点也只呈现边界被测试或压力换形态。
- 节点和版本增加显式路径记忆，覆盖婚育边界、辞职、转岗、迁移、分手、共同生活、健康警讯、买房、负债、收入变化和自由职业；后续候选会过滤已经发生过的第一次行动。
- 继续五年、10/15/20 年观察跨度和现实强度设置。
- 已保存版本切换和逐年版本对照。
- 本地历史记录、旧数据迁移、JSON 导入和导出。
- 时间推演返回人物档案、人物档案返回人物空间的连续导航。
- DeepSeek 官方 API 已作为服务端内容引擎接入，固定使用 `deepseek-chat` 非思考模式。配置后可生成结构化追问、困局摘要、三项行动和三年余波；结构不合格、超时或请求失败时自动回退到本地婚育、健康、城市和通用内容。
- 左侧导航及手机顶部持续显示模型状态。服务端通过最小真实请求确认 DeepSeek 连通并缓存五分钟，成功后才显示绿色“DeepSeek 已接入”；失败时显示“本地推演模式”。
- 普通用户不再填写 API 地址、模型名或密钥。密钥只从被 Git 忽略的服务端 `.env` 或运行环境读取，前端只读取可用状态，请求体和人物备份都不包含密钥；旧版浏览器 AI 配置会在启动时清除。
- DeepSeek 入口只接受同源 JSON 请求，模型限制为 `deepseek-chat`，不能通过客户端切换上游或开启 `deepseek-reasoner`。输入困局前明确提示哪些人物内容会发送给 DeepSeek。
- 人物及其全部版本可以删除。

## 数据语义

- localStorage 主键：`forked-life-workspace-v2`。
- 旧数据主键：`future-life-state`，加载时自动迁移。
- 未保存草稿及首次尚未保存的人物只存在于当前页面内存，不进入 localStorage，也不增加版本数量；刷新会放弃它们。
- 保存草稿后创建新版本并切换为活动版本。
- 修改人物画像不会修改版本节点中已经保存的状态。
- 新建流程的追问、回答、困局摘要和候选路径保存在 `person.intake`；保存版本时会冻结 `choiceMeta`、`assumptions` 和 `pathMemory`。

## 已知限制

- 因果模型当前仍是规则驱动的 v1，重点覆盖首次三年；已有版本的长期延伸仍主要依赖预设事件和数值传播，人物之间可能趋同。
- 路径记忆已经结构化扩展到多类高强度事件，但后续本地选项库仍主要覆盖婚育、健康、城市和通用策略，尚未为分手、买房、负债等每类事件写完整的余波库。
- 首次困局、路径和年度节点已经展示因果依据，已保存版本对照页尚未按关键变量解释差异；产品仍不展示缺少证据基础的概率数字。
- 场景视觉由本地 CSS 生成，尚无真实 CG 素材。
- 数据只保存在当前浏览器，没有账户、云同步和跨设备恢复。
- DeepSeek 目前只增强新建人物的首次三年推演；已有版本的普通节点改写仍使用本地选择与余波。
- 尚未进行目标用户测试，当前判断主要来自产品创建者的连续体验反馈。
- 版本目前不能重命名或删除；人物已经可以删除。
- 完整增强循环已经实现为可体验原型，但尚未进行目标用户验证，不能据此判断它已经形成长期留存。

## 最近反馈

2026-08-27 用户指出关系/出行型自定义路径的第二年因果栏位逻辑松散，并且“男友主动见她”却显示关系持平。根因是自定义行动的通用占位机制进入了模型上下文，且校验只检查数值范围、没有检查叙事与状态方向。现已增加因果语言质量校验、上下文化兜底和关系投入一致性修正。

2026-08-27 用户要求接入 DeepSeek 官方 API，使用快速模型且不开思考模式。产品已改为服务端统一使用 `deepseek-chat`，移除普通用户的模型配置入口，并保留结构校验和本地回退。

用户认为产品已经比早期原型更像完整产品，但仍不能充分吸引用户兴趣。当前判断是：界面和管理能力已经超过推演内容本身，下一步不应只继续增加页面，而应验证个性化事件、选择张力、现实代价和逐步揭晓是否能形成留存。

2026-08-24 用户确认因果模型是重要问题。本轮将首次推演改为结构化因果链：追问补充真正会改变路径的变量；选择前展示行动机制和复盘信号；年度节点区分原因、结果与不确定项；首次只保存三年可解释范围，不再把自动十五年基线当成用户选择。该模型仍需目标用户判断“因果是否可信”，不能因为字段完整就视为成立。

当前已经确认把内容吸引力研究转成需求。本轮在原有窄范围原型上接通了首次困局完整闭环，但仍把它视为待用户验证的产品假设。

2026-08-17 新增内容研究并转成需求：外部数据和竞品机制都指向“短钩子、连续后果、个人相关性、选择代价”。用户已确认三年余波要逐年揭晓，隐藏代价通过剧情自然体现，AI 可以参与生成候选三年余波但必须有本地规则兜底；现实困局要前置到创建人物流程，由用户输入，AI 只负责整理、追问和结构化。

2026-08-18 用户确认首次输入后需要追问、需要“这都不是她/他/TA会做的”自定义行动入口，并接受第一阶段三年后先保存、换路或修改条件。首次追问确定为自适应 1 至 3 问：一次一题，选项加自由补充，已经明确的信息不重复询问。页面交互、结构化 AI 候选、本地回退、路径记忆和隐私删除入口均已实现。
