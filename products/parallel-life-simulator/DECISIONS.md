# 岔路人生：产品决定

本文件记录已经确认、已经否决和仍待决定的事项。后续讨论出现冲突时，以用户最新明确决定为准。

## 已确认

### 定位与表达

- 产品名称为“岔路人生”，不再使用“未来生命”或“时光旅人”。
- 面向普通用户，同时支持自我探索和创建非自己的人物。
- 使用第三人称观察人物未来。
- 产品应冷静可信，同时具有未来感和沉浸感。
- 推演对象是一生中的现实轨迹，允许人的追求与观念发生变化。
- 用户不需要先阅读分析报告，信息应通过时间轴、事件和选择被感知。

### 人物与版本

- 人物必须包含身体、精神、关系、事业、金钱、追求和观念弹性等多方面画像，使用 0-100 数值。
- 可按身份给出起始估计，但用户可以自行调整。
- 同一人物可以拥有多个推演版本。
- 人物画像更新只影响之后的新推演，不回写旧版本。
- 人物档案桌面布局为左侧画像、右侧信息，并尽量控制在一屏内。
- 新建人物使用轻量现实困局流程，不要求用户先理解或调整七维画像；完整画像保留在创建后的编辑入口。

### 时间轴与改写

- 时间轴以年为节点，使用五年浏览窗口，同时保留完整人生总览。
- 节点密度不能只有四五个；默认轨迹需要形成足够完整的人生阶段。
- 每个节点都可以被改写。
- 改写发生后，当前年份及后续节点在同一条路径上重新推演，前面的节点保持不变。
- 改写后先形成未保存草稿，不能立即在版本列表增加版本。
- 只有点击“保存新版本”后，草稿才成为人物的新版本。
- 可以放弃未保存改写，回到原版本。
- “继续五年”生成的内容同样先作为草稿，保存后才形成版本。
- 当前先验证一次节点改写的吸引力，不因此重做完整产品循环。
- 节点改写让用户选择三项具体生活行动，并在选择前说明眼前收益与现实代价；不再向用户暴露抽象的“变化幅度”滑杆。
- 选择后最先三年需要有明确因果连续性，再逐渐回到开放推演；不能只替换相似标题。
- 改写后的前三年必须按“行动发生 -> 代价显形 -> 验证、反噬或再协商”设计成连续叙事单元，并通过逐年揭晓驱动用户主动查看下一年。
- 每个改写选项必须有选择前可见的眼前收益与现实代价，并在选择后的节点中自然揭示至少一个当时未完全预见的隐藏代价；隐藏代价不需要额外 UI 标签。
- 年度节点标题和摘要应从状态报告转向克制的生活钩子：具体、可感、有现实悬念，但不得狗血化或命运化。
- 压力不按只增不减的单一数值呈现。人可能适应、麻木或合理化，代价可以转移到行动意愿、关系和自我判断，也可能被后来事件重新激活。
- 父母催婚属于外部压力，不代表结婚是正确或必然结果。推演必须允许不婚、晚婚、丁克、暂不决定或之后改变想法，保护的是人物的决定权。
- 同一条路径里，已经完成过的高强度表态不能被后续节点当成第一次重新发生。若人物已经和父母说清婚育边界，后续只能呈现旧边界被测试、关系余波、压力换形态或边界维护，不能再次写成“又摊牌一次”。
- 高强度事件都应进入路径记忆，不限于婚育边界；辞职、转岗、迁移、分手、共同生活、重大健康警讯、买房、负债和收入结构明显变化等事件，后续不能当成第一次重复发生。

### 内容与 AI

- 创建人物流程必须前置收集现实困局，包括最近最烦的一件事、最想保住的东西、最不想承认的担心、正在施压的关系和当前最怕付出的代价。现实困局主要由用户输入，AI 可以整理、追问和结构化，但不能凭空替用户编造真实困局。
- 第一批内容原型优先使用交叉困局：职业停滞、家庭或亲密压力、钱和安全感。暂缓纯恋爱爽文、纯职场升级、纯财富逆袭和纯心理疗愈。
- AI 只能服务结构化推演：归纳困局、生成三年余波候选事件、补充隐藏代价、写第三人称旁白或给出假设依据。AI 不得替代主体验成为开放陪聊、人生建议或长报告生成器；AI 不通、超时或内容不合格时必须回退到本地规则。
- 首次输入现实困局后，AI 应根据已知信息自适应追问 1 至 3 个问题，三问是上限而不是必须凑满的数量；已经明确的信息不得重复询问。
- 追问一次只展示一题，以容易选择的上下文选项为主，并允许“暂时说不清”和自由补充。追问结束后先展示系统对困局的理解，用户确认或修正后再生成路径。
- 三条系统路径之外必须提供“这都不是她/他/TA会做的”，允许用户输入自己的行动再推演。
- 第一阶段看完三年余波后只提供保存当前路径、尝试另一条路径和修改条件，不立即进入每年一次的无限选择循环。
- “更现实”允许在有上下文依据时呈现失业、收入下降、关系疏远或持续疲劳，但不能在没有用户输入依据时凭空制造重病、死亡、背叛、暴富或巨额负债等极端事件。
- AI 返回的追问、困局摘要、路径和三年余波必须经过结构与内容边界校验；失败、超时或不合格时自动使用本地候选，不向用户暴露开放聊天。

### 导航与保存

- 产品首页是人物空间。
- 时间推演必须提供明确的“返回人物档案”入口；人物档案必须能返回人物空间。
- 人物、版本和历史记录保存在浏览器本地，并支持 JSON 导入和导出。
- 当前产品默认不依赖外部 CDN、账户或 API Key；可选的本地 AI 连接器允许用户在本机保存 OpenAI 兼容的 base URL、模型名和密钥，并通过同源代理调用 `/api/llm/chat`，默认模型名为 `gpt-luna`。代理必须限制请求形态，非本机上游默认要求 HTTPS，不能成为任意开放转发器。
- 启用外部模型前必须说明现实困局、回答和人物上下文会发送到所配置的上游；用户可以清空模型配置与密钥，也可以删除人物及其全部本地版本。

## 已否决

- 黄色小分支线：完全移除，不再作为时间轴表达。
- 点击节点改写后立即生成独立版本：违背草稿语义，不得恢复。
- “继续改写”按钮：与“改写这个节点”功能重复，已删除。
- 只有四五个稀疏节点的时间线：过于像玩具。
- 以分析报告作为主要结果页：不符合用户希望的体验。
- 用省略号截断关键的分支或节点标题，导致用户看不到完整文字。

## 待决定或待验证

以下内容尚未得到用户的实施确认：

- 为关键节点加入时间抵达动画和真实横版 CG。
- 引入可解释的概率、因果依据和假设标记，提高推演可信度。
- 是否增加账户、云端同步和跨设备数据。
- 是否开展外部用户测试，以及以哪些留存行为作为验证指标。
